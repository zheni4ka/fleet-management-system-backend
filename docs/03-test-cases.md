# Тестування та відлагодження

Документ закриває вимоги лабораторної роботи № 6: тест-кейси, результати тестування, відповіді програмістів і документальне оформлення результатів.

## 1. Об'єкт і умови тестування

| Параметр | Значення |
|---|---|
| Об'єкт | Система обліку автопарку й логістики маршрутів (бекенд ASP.NET Core + фронтенд Next.js) |
| Середовище | Windows 11, .NET 10 SDK, SQL Server LocalDB, браузер Chromium |
| Види тестування | Функціональне (API і UI), негативне (валідація), перевірка прав доступу, аналіз коду |
| Тестові дані | Адміністратор зі `IdentitySeeder`, тестовий диспетчер, довідники з `ModelBuilderExtensions` |

Статуси: **Пройдено** — фактичний результат збігся з очікуваним; **Не пройдено** — виявлено дефект; **Не виконано** — кейс підготовлено, але ще не прогнано. Позначка «аналіз коду» означає, що дефект знайдено під час перегляду коду, а не під час запуску.

## 5. Висновок

Нові функції (розширений пошук маршрутів, звіт за період, валідація періодів, обмеження доступу до нових ендпоінтів) пройшли перевірку через API. Усі 8 дефектів виправлено. D-01 – D-06 і D-08 повторно перевірено через API, а D-07 — перевіркою типів і лінтером (у браузері сторінку не відкривали). Секрети зберігаються поза репозиторієм; як їх налаштувати, описано в [README.md](../README.md). Тест-кейси зі статусом «Не виконано» треба прогнати вручну в браузері й записати фактичні результати в цю таблицю.

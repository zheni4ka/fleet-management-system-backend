# Сценарій демонстрації (5 хвилин)

## Підготовка (до виступу)

1. Окрема БД для показу, щоб не чіпати робочі дані:
   ```bash
   dotnet ef database update --project data_access --startup-project transport-logistic-management-2026 --connection "Server=(localdb)\mssqllocaldb;Database=FleetDemo;Trusted_Connection=True;MultipleActiveResultSets=true"
   ```
2. Секрети (один раз): `SeedAdmin:Password` і `DemoSeed:DispatcherPassword` — див. [README](../README.md#демонстраційні-дані).
3. Заповнити БД і запустити API та фронтенд:
   ```cmd
   set ConnectionStrings__connectionString=Server=(localdb)\mssqllocaldb;Database=FleetDemo;Trusted_Connection=True;MultipleActiveResultSets=true
   dotnet run --project transport-logistic-management-2026 --launch-profile http -- seed-demo
   dotnet run --project transport-logistic-management-2026 --launch-profile http
   ```
   У теці фронтенду: `npm run dev`, сторінка http://localhost:3000.
4. Відкрити дві вкладки браузера: у першій увійти як `dispatcher.kyiv`, другу залишити для адміністратора `admin`.
5. Заздалегідь знайти на сторінці «Маршрути» запланований рейс Київського депо на наступний тиждень і запам'ятати його авто, водія й час — він знадобиться для кроку 3.
6. Інтерфейс — українською (перемикач UA/EN у шапці).

## Результат дослідження: одночасні запити

Сценарій k6 надсилає N одночасних запитів на створення рейсу з тим самим авто, водієм та інтервалом і перевіряє, що в БД збережено рівно один рейс:

```cmd
set API_BASE_URL=http://localhost:5196/api/v1
set DISPATCHER_PASSWORD=<DemoSeed:DispatcherPassword>
set PARALLEL_REQUESTS=50
k6 run load-tests/conflicting-route-creation.js
```

Очікуваний підсумок (перевірено на SQL Server LocalDB з демо-даними):

```
Conflicting route creation
  parallel requests:   50
  201 Created:         1
  409 Conflict:        49
  unexpected answers:  0
  invariant held:      yes
```

Якщо створено не рівно один рейс або з'явилася інша відповідь, ніж 201/409, k6 завершується з ненульовим кодом (пороги `created_routes: count==1`, `unexpected_responses: count==0`). Скрипт сам вибирає вільне авто й водія одного депо та інтервал далеко в майбутньому, тож його можна запускати повторно на тих самих даних.

## Якщо щось пішло не так

- «The database already contains vehicles» під час `seed-demo` — БД не порожня; створіть нову (крок 1 підготовки).
- 401 у k6 — неправильний `DISPATCHER_PASSWORD`; 429 — перевищено ліміт входів (10 за хвилину з однієї IP-адреси), зачекайте хвилину.
- Пошук міст у формі маршруту працює через Open-Meteo, тож потребує інтернету; перевірте з'єднання перед виступом. Без нього кроки 2 і 3 не вдасться показати, а кроки 4–7 працюють і офлайн.
